# 验证记录

## 应用基线：AI Camera Lab v1.0

以下为独立仓库整理前，同一组摄像头应用源文件在 ESP32-S31-Korvo-1 上的实机记录。原始日志、设备唯一标识和真实摄像头截图不随源码发布。

| 项目 | 结果 |
| --- | --- |
| 连续运行窗口 | 533 秒，约 9 分钟 |
| USB 格式 / 采集 | 640 × 480 MJPEG，约 15 FPS |
| USB 界面呈现 | 最后稳定窗口平均 9.03 FPS |
| 板载 DVP | 640 × 480 RGB565，约 5.51 FPS |
| 交互 | 主副画面切换 13 次；冻结、纯画面模式各切换 2 次 |
| 人脸功能 | 完成一次三样本录入，42 次特征比对尝试；未统计成功匹配次数 |
| AI 任务 | 确认运行于 Core 1，ELF 包含 PIE V2 指令；JPEG 使用硬件驱动 |
| AI 耗时 | 观察到检测约 29–51 ms；含特征提取 / 比对的最大耗时 386 ms |
| 错误 | JPEG 解码错误 2 次；USB 传输、DVP 采集、AI 错误计数均为 0 |
| 显示 / 系统 | LCD underrun 计数为 0；窗口内未记录 panic、watchdog 或栈保护异常 |

识别准确率、不同光照 / 人群下的表现、其他 UVC 摄像头兼容性以及长时间可靠性尚未系统评估。当前独立版本的完整 USB 热插拔回归也未完成。

显示链路已加入双缓冲、内部 RAM bounce buffer、帧引用保护和任务核分配调整。偶发黑闪尚未获得更长时间的实屏确认，不能据此宣称完全解决。

## 独立源码构建

2026-09-11，在独立目录中使用 [构建说明](BUILD.md)的 SDK、工具链与 `python tools/build.py --jobs 12` 完成了首次完整构建：

- CMake 配置、2,085 个 Ninja 构建步骤、链接与应用分区大小检查均通过。
- Component Manager 重新解析并锁定 22 个依赖项（含 IDF），各组件版本与原工程使用的版本一致。
- 应用 `camera_lab.bin` 为 **4,614,272 字节**，适配 8 MiB 应用分区，余量约 45%。构建产物未纳入源码仓库。
- 核对 521 个 CPU、PSRAM、USB、LVGL、模型、DVP、FreeRTOS、栈保护和 Flash 配置项：519 项一致，2 项仅为分区文件名变化。
- 摄像头运行逻辑保持不变，整理涉及独立 CMake、依赖声明、板级相对路径及说明文件。

此次验证使用已有 SDK 与组件缓存，并访问官方组件仓库重新解析依赖；不等于从空白电脑开始验证安装。本轮未再次烧录开发板。这里的编译结果与上面的实机应用记录分别列出，不能视为对重新构建固件完成了一轮新的实机测试。
