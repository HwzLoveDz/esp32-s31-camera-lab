# 调试

串口控制台使用 115200 波特率。通过 `idf.py -p PORT monitor` 或串口工具连接，其中 `PORT` 替换为当前开发板端口。

| 命令 | 用途 |
| --- | --- |
| `camera_status` | 输出摄像头、AI、UI、内存和运行时间统计 |
| `camera_action swap` | 交换主副画面 |
| `camera_action freeze` | 切换冻结 / 实时预览 |
| `camera_action clean` | 切换纯画面 / 完整界面 |
| `camera_action gallery` | 打开或关闭人脸库 |
| `camera_action add` | 开始录入 |
| `camera_action cancel` | 取消录入 |
| `camera_action delete` | 执行界面对应的删除操作，同样需要二次确认 |
| `camera_screen` | 将当前 LVGL 画面缩小为 400 × 240，通过串口输出 RGB565 十六进制像素 |

`camera_screen` 会短时复制显示缓冲，并输出较多串口数据，适合布局检查，不适合用于持续录像。导出内容可能包含人脸、房间和屏幕上的其他信息。它是显式的本地调试操作，不会上传到网络。

## 阅读统计

- USB 采集帧率、解码帧率和界面呈现帧率是不同指标。显示采取保留最新帧的策略，显示丢帧计数不等于 USB 传输失败。
- `recognized` 字段目前统计特征比对尝试次数，不是成功识别次数；不要据此计算准确率。
- AI 耗时随检测、特征提取、比对和画面内容变化。最大耗时不应当作稳定每帧耗时。
- `HOLD` 冻结的是显示，采集和 AI 仍然运行。
- LCD underrun 为零只说明计数中没有捕获该事件，不能代替对实际屏幕闪烁的观察。

提交问题时建议包含：板卡版本、摄像头型号与格式、SDK 提交、复现步骤，以及去除设备唯一标识的相关日志片段。不要提交完整 Flash / NVS 转储、人脸样本或未检查的截图。
